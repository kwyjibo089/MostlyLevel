# Changelog

Notable project changes are recorded here. This file was introduced with the initial project documentation; earlier implementation history is not available from the top-level repository metadata.

## Unreleased

- Nicer HORIZON graphics:
  - the pitch arc is a smooth ring of constant width, with ticks pointing at the centre and labels following the curve (no labels at the ±40 ends);
  - the camper is redrawn from shapes: rounded body, sloped windscreen, round wheels with rims, wheel arches, and a clean outline (`tools/make_van.py` generates `src/van_sprite.py`).

  Both are kept as small bitmaps that the compositor copies in with `framebuf.blit` (new `compositor.Bitmap`; the screenshot and direct-drawing paths support them too), so redraw speed is about unchanged and free memory about 4 KB lower. A 6-minute stress run on the board stayed stable. Reference images regenerated and reviewed.
- German numbers use a decimal point instead of a comma (owner choice, Swiss convention).
- CALIBRATE and the language button now need a press of about one second (`LONG_PRESS_MS` in `config.py`); a bar along the button fills while holding, and releasing or sliding off cancels. A stray touch can no longer overwrite the level reference or switch the language. Checked on the board with a simulated touch; not yet with a finger.
- Pitch and roll readouts use P and R in every language (owner choice), instead of L/Q (German), T/R (French), and L/T (Spanish).
- Moved the language switch from the header, where the printed case made it almost unreachable, to a cyan rounded button on the HORIZON page, left of CALIBRATE on the same line; its touch area is slightly larger than the button. The header looks as it did before languages were added. Reference images regenerated and reviewed.
- Screen texts moved to per-language files with German, French, and Spanish translations, switchable at runtime. Tap the new language chip in the header to cycle EN → DE → FR → ES; the choice is saved in `/language.cfg`. Texts are in `src/lang_<code>.json` and loaded by the new `src/i18n.py` (only the active language stays in memory); `LANGUAGES` and `DEFAULT_LANGUAGE` are in `config.py`. Numbers use a decimal comma in German, French, and Spanish. The font gained a comma and accented capitals (Ä Ö Ü À Á É È Ê Í Ó Ú Ñ Ç), drawn as full-height letters with the accent above the line. Other visible changes:
  - the header status labels are shorter so they fit (`CONNECTING` was cut off; now `LINKING`, and `GATT` became `SETUP`);
  - the LEVELLING "no wedges needed" message is centred.

  Reference images were regenerated and reviewed, and per-language scenes were added. Deploy and switching were checked on the board; tapping the chip on the device and the translations themselves are not yet reviewed.
- The BLE client now recovers from stuck links instead of waiting for a reset. `maintain()`, called every main-loop step, disconnects if needed and rescans:
  - after 5 s in ERROR;
  - after 20 s stuck connecting, discovering, setting up, or disconnecting;
  - after 30 s scanning without a scan-done event;
  - after 10 s connected without data.

  After 5 recoveries without new data the board hard-resets; a switched-off sensor just keeps scanning. Settings are in `config.py` (`SENSOR_ERROR_RETRY_MS`, `SENSOR_SETUP_TIMEOUT_MS`, `SENSOR_SCAN_TIMEOUT_MS`, `SENSOR_SILENT_RECONNECT_MS`, `SENSOR_RECOVERY_RESET_COUNT`). A forced recovery with the real sensor on the board reconnected and returned to LIVE.
- The main loop now survives unexpected errors instead of stopping with a frozen screen: `run()` logs the error, waits 1 s, redraws everything, and hard-resets the board after 5 errors in a row; if startup fails it resets after 10 s (`STEP_ERROR_RETRY_MS`, `STEP_ERROR_RESET_COUNT`, `SETUP_ERROR_RESET_MS` in `config.py`). Ctrl+C still stops the app. Checked on the board with injected errors.
- Faster HORIZON redraws: font glyphs are drawn as merged rects (identical runs on adjacent rows or columns combined; about half as many rects for text, pixel-identical), and the compositor sorts rects into strips with a fast path for the common single-strip case. On the board a live redraw step dropped from ~224–232 ms to ~134–141 ms (measured back to back with a stub sensor). Text on the LEVELLING page benefits too. Not yet observed by the owner.
- Documentation only: the owner reported the composited LEVELLING page as a lot better on the device (2026-10-16).
- LEVELLING page drawn flicker-free like HORIZON: a changed value is composited off-screen (only that value line) and sent in one transfer; page, tab, and layout changes composite the whole page through the strip renderer, which is now shared by both pages (`page_renderer`). Page and tab switches no longer clear the screen to black first. On the board this is also faster than before (value update ~130–150 ms instead of ~200–220 ms; switching pages ~0.4 s quicker). Pixel output is unchanged in the desktop tests; not yet observed on the device.
- Documentation and a `config.py` comment only: recorded the owner's 2026-10-16 device checks. The image is clean at 40 MHz SPI, updates show almost no flicker or lag, and switching the sensor off shows the disconnect warning, with a return to LIVE once it is back on.
- Documentation only: recorded an on-board comparison of `.mpy` and source modules. Importing the app takes ~190 ms instead of ~720 ms, temporary allocation during import is ~5 KB lower, and steady-state free memory is about the same (~91.9 KB versus ~90.7 KB). Corrected the README and `build_mpy.sh` rationale accordingly.
- Faster live HORIZON updates. Measured on the board with a stub sensor, a redraw step dropped from ~390–400 ms to ~170–230 ms: the app now collects garbage before each live redraw (repeated collections on a fragmented heap were the largest cost), records the fixed layers (pitch arc, van, CALIBRATE button, level frame) and font glyph runs once, and runs the LCD SPI at 40 MHz instead of 20 MHz (the reference BSP's clock). `RENDER_INTERVAL_MS` is now 100 instead of 250, so the screen follows movement about every 0.3 s instead of ~0.6 s. Rendering is pixel-identical in the desktop tests; image quality at 40 MHz is not yet confirmed by eye.
- A lost sensor connection now shows `NO LINK` in the header and `SENSOR DISCONNECTED` in the warning until the sensor is streaming again. Previously the BLE client's immediate rescan made it look like a first-time `SCANNING` / `WAITING FOR SENSOR`. `ble_read.py` gained a `link_lost` flag (set on disconnect, cleared when notifications are enabled); `app.py` maps it to the `DISCONNECTED` state. Reconnection is unchanged. Added the `flow_disconnected` reference image and reconnect tests; not yet observed on hardware.
- Licensed MostlyLevel's own code under MIT (`LICENSE`). Added `THIRD_PARTY_NOTICES.md` with the Adafruit BSD notices for the ILI9341 initialisation values (byte-identical to Adafruit_ILI9341's `initcmd`) and the 5×7 font (26 of 43 glyphs identical to Adafruit GFX `glcdfont.c`; exact origin not established), plus notes on the MicroPython firmware (SHA-256 matches the official download) and the Espressif Apache-2.0 reference BSP. Added `firmware/MICROPYTHON_LICENSE` and the Apache-2.0 text as `reference/esp32_s3_es3c28p/LICENSE`. Comment-only attribution headers in `src/ili9341.py` and `src/graphics.py`; no behavior change.
- Documentation and a `config.py` comment only: recorded the owner's 2026-10-16 hardware check of the axis signs. On the installed van, raising the front gives positive pitch, raising the left side gives positive roll, and the LEVELLING page points to the correct wheels. No setting changed; lift-estimate accuracy remains unmeasured.
- Deploy precompiled modules: `tools/build_mpy.sh` builds `build/mpy/` (all modules as `.mpy` except `main.py` and `config.py`), and `tools/deploy.sh` now uploads that bundle by default, checks the board's `.mpy` version first, and removes stale `.py` copies of precompiled modules; `-s` uploads sources as before. CI builds the bundle after the tests and publishes it as an artifact. Added tests for the build, deploy, and screenshot scripts against a fake `mpremote`; both scripts accept `MPREMOTE`, and `screenshot.sh` accepts `ASSETS_DIR`, for that purpose.
- Moved the dashboard from `src/main.py` into `src/app.py` with `setup()`, `step()` (one main-loop pass), and `run()`; `main.py` now only imports the app, re-exports `save_screenshot` for the REPL, and calls `app.run()`. Behavior and rendering are unchanged (all reference images still match). In the REPL, the sensor is now `app.sensor`. Added integration tests that drive `step()` with a simulated sensor over the real BLE client, fake touch, and a fake clock: startup, live data, battery polling, stale data and recovery, redraw throttling, touch calibration with persistence across restart, refused calibration, page navigation, disconnect, touch failure, and the entry point. Upload the new `app.py` together with `main.py`.
- Added automated tests and CI: fake `machine`/`bluetooth`/`framebuf` modules and an ILI9341 panel model in `tests/fakes/`; unit tests for decoding, the BLE client, levelling maths, axis mapping, calibration, touch, driver, and compositor; rendering-invariant tests; reference images for eight page/state scenes; `tools/test.sh` (ruff, `mpy-cross` compile check, pytest); and a GitHub Actions workflow for pull requests into `main`. Removed an unused import from `src/graphics.py`. Recorded the board's reported firmware (MicroPython 1.29.0, `ESP32_GENERIC_S3`).
- Added `tools/screenshot.sh`, which captures the running dashboard as `assets/<name>.png` in one step (save on the board, copy, delete on the board, convert with ImageMagick, reset). Tested against a stand-in `mpremote` only; not yet run against the board.
- Moved the header, navigation, CALIBRATE button, LEVELLING tabs, and the top of both pages down by `SCREEN_TOP_INSET` (10 rows, in `config.py`) because the owner's printed case hides roughly the top 9 rows. Bottom and side positions are unchanged; the LEVELLING cells keep their bottom edges and become shorter, and touch areas follow the moved controls. With an inset of 0, a desktop simulation reproduces the previous layout pixel for pixel; the new layout has not yet been checked in the case.
- Composited the HORIZON page off-screen to remove the remaining redraw flicker: drawing is recorded as filled rects (`src/compositor.py`), painted into a 240 × `HORIZON_STRIP_ROWS` RGB565 strip buffer, and sent one strip per transfer, skipping strips whose content did not change. Every pixel is written once with its final colour, so the arc, ladder, van, button, and readouts no longer blink. This replaces the A4 exclusion rects, button-corner repaint, and per-character readout updates. If the strip buffer cannot be allocated, smaller strips and then direct drawing are used. A desktop simulation matched the previous rendering pixel for pixel. The owner reported the result on the device as a clear improvement; redraw timing has not been measured.
- Added `tools/deploy.sh`, which uploads the app files in one `mpremote` session (unchanged files are skipped by hash) and resets the board; documented it in the README. Tested against a stand-in `mpremote` only, not yet against the board.
- Reduced HORIZON flicker: live redraws skip the CALIBRATE button, the pitch/roll readout boxes, and (while level) the green frame, so these are no longer erased and repainted on each update. `Graphics` gained exclusion rects that clip all drawing, including ladder lines, around those areas. The horizon behind the button's rounded corners is repainted separately only when its colour changes, and the readouts repaint only changed characters. A desktop SPI simulation matched a full redraw pixel for pixel after every update; the moving arc, pitch ladder, and van still redraw each frame, and on-device behavior is not yet observed.
- Reduced LEVELLING page flicker: the layout is drawn once on page or view changes, and later updates repaint only cells whose displayed text changed (full content redraw only when switching to or from the "no wedges needed" message). The ILI9341 driver now reuses per-colour fill buffers (sized by `LCD_FILL_CHUNK_PIXELS`/`LCD_FILL_CACHE_COLOURS` in `config.py`) and a fixed window buffer, and sends each rectangle in one chip-select transaction. A desktop SPI simulation produced identical pixels before and after; on-device speed and flicker are not yet measured.
- Fixed `save_screenshot` subtracting the level-reference offsets a second time and hard-coding the sensor axis swap; it now inverts the configured mapping so the BMP matches the last rendered attitude. Fixed the `ble_read.py` console diagnostic's measurement format string, which mixed `%` and `{}` placeholders and raised `TypeError`. Neither fix has been run on hardware.
- Added a persistent level-reference calibration action on the HORIZON screen, a prominent red warning for unavailable sensor data, and separate 0.5°/0.7° level-frame on/off thresholds. Styled `CALIBRATE` as a rounded yellow button in the upper-right above the horizon arc. Grouped repeated horizon and ladder drawing operations, batched LCD address-window commands, and rasterized text in horizontal runs to reduce redraw flicker; hardware speedup remains to be measured.
- Added a thicker green frame around the HORIZON display region when live pitch and roll are both within ±0.5°; inset the pitch/roll readout boxes with clear spacing. The threshold is configurable.
- Added `src/config.py` for sensor identity/protocol settings, sensor axis mapping and scaling, vehicle geometry, display timing, and LCD/touch wiring; updated the client, scanner, and drivers to use it.
- Updated the README screenshot gallery with the HORIZON, 4 CORNERS, and 2 WEDGES screens.
- Renamed the first touchscreen page button from `LEVEL` to `HORIZON` to describe its virtual-horizon display.
- Added a touch-selectable second page that ranks the estimated wheel-corner lift heights and shows the two largest for a two-wedge setup. Values use pitch, roll, wheelbase, and front/rear track width. The FT5x06-compatible touch reader uses reference board wiring; physical touch behavior and corner-height sign assumptions remain unverified.
- Added a `4 CORNERS` view alongside `2 WEDGES` on the `LEVELLING` page, with touch tabs; `2 WEDGES` remains the default.
- Added an automatic battery percentage read every 60 seconds and display beside `LIVE` in the top bar. The 385 (3.85 V) reading maps to 60% using a related WT9011DCL-BT50 voltage table and matched the Android app on the connected unit.
- Removed the compass and expanded the virtual horizon to occupy the display area below the status and pitch/roll readout bars.
- Swapped decoded pitch/roll channels at the display boundary to match the owner's reported sensor movement; signs still need hardware confirmation.
- Avoided full-screen clears during normal updates; the header now redraws only on connection-status changes, and the readouts/horizon redraw only when displayed pitch or roll changes.
- Added a 0.2° attitude redraw deadband to suppress display updates from small sensor fluctuations.
- Added an on-demand software-rendered BMP screenshot function using an 8-row tile buffer after controller MISO readback returned all-zero pixels and a full-screen buffer allocation failed.
- Replaced the static demo screen with a mockup-inspired attitude and compass dashboard driven by the WT901 BLE client.
- Refactored `ble_read.py` into an import-safe client while retaining its console diagnostic mode.
- Added project guidance, context, architecture, hardware, and decision documentation.
- Documented MicroPython source deployment and startup steps in the README.
- Hardware rendering and sensor notification behavior remain unverified.
